# PicoPilot

This is a personal **PET project** for experimenting with an Attitude and Heading Reference System (AHRS) and flight-control-related embedded software on a Raspberry Pi Pico.

It is **not intended for real-world or production use**. The project is experimental, incomplete, and may contain incorrect assumptions, unhandled failure modes, timing issues, and unsafe behavior. Do not use it to control a real aircraft, vehicle, or other system where a failure could cause injury or damage.

## Current Scope

The firmware currently brings together:

- MPU6500 IMU support
- BME280 barometer support
- NEO-6M GPS support
- Sensor-fusion and altitude-related calculations
- Basic control and motor output handling
- PPM receiver input
- USB/UART telemetry
- DMA, multicore, interrupts, I2C, UART, PWM, and GPIO usage

The target hardware is a Raspberry Pi Pico using the Pico SDK and a C++17 build.

## Pros

- Provides hands-on experience with embedded C++ and the Raspberry Pi Pico SDK.
- Combines several common navigation and control sensors in one project.
- Uses hardware features such as interrupts, DMA, multicore processing, and PWM.
- Separates several device drivers and functional areas into individual modules.
- Includes a foundation for experimenting with sensor fusion, telemetry, and control algorithms.
- Uses a generated telemetry packet format suitable for communication with an external tool.

## Cons and Limitations

- The code is a work in progress and has not been validated for reliable or safety-critical operation.
- Sensor calibration, filtering, coordinate conventions, and estimation accuracy require further review.
- Control behavior and failsafe handling need more testing, especially during sensor, receiver, GPS, and communication failures.
- Timing, concurrency, shared state, and interrupt behavior may still contain race conditions or edge cases.
- Hardware assumptions and pin assignments are currently closely tied to this particular setup.
- Automated tests, hardware-in-the-loop tests, documentation, and diagnostic tooling are limited.
- There is no guarantee of stable API, telemetry, or configuration compatibility.

## Improvements Needed

Before this could be considered for anything beyond experimentation, it would need substantial work, including:

- Thorough unit, integration, hardware-in-the-loop, and flight testing.
- Explicit startup checks, watchdog handling, and robust failsafe behavior.
- Better sensor calibration and validation of all coordinate frames and units.
- Review and tuning of the attitude, altitude, and control algorithms.
- Safer configuration management instead of relying primarily on compile-time settings.
- Clearer error reporting and telemetry diagnostics.
- More comprehensive documentation for wiring, hardware versions, and pin assignments.
- Static analysis, formatting, code review, and stronger automated test coverage.
- Independent safety review before connecting the software to any hazardous hardware.

## Building

The project uses CMake and the Raspberry Pi Pico SDK. A configured Pico development environment is required.

The VS Code project includes a `Compile Project` task that builds the configured project in the `build/` directory. The resulting firmware artifacts are generated by the Pico SDK.
